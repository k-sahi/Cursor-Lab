# Coding practices

The conventions this codebase follows. The enforceable version for Cursor's agent is `.cursor/rules/coding-standards.md`; both are generated by the `/generate` skill.

## Project overview

- Two apps in one repo: `TaskFlow-Backend/` (Express 5 REST API on MongoDB) and `TaskFlow-API/` (React 19 single-page UI). The naming is historical: `TaskFlow-API` is the front end.
- The back end is stateless: JWTs carry the user, MongoDB holds everything else. Every resource is owned by a user and every query filters by owner.
- Tasks live under projects (`/api/projects/:projectId/tasks`); notifications are a side effect of every write, and email is a best-effort side effect of project create and delete.
- `src/app.js` builds the app; `server.js` only checks config, connects to MongoDB and listens. Tests mount `createApp()` directly.

## Repo conventions

**Directory structure.** `routes/` (one router per resource), `models/` (one Mongoose model per file, constants as statics), `middleware/` (`requireAuth`, `errorHandler`), `services/` (side effects), `utils/` (`logger`, `validation`), `config.js` (env access). Migrations in `scripts/`, tests in `test/`.

**Naming.** camelCase for functions and variables, PascalCase for models and React components, `UPPER_SNAKE_CASE` for allowed-value lists, snake_case for enum values (`in_progress`) and notification types (`task_created`). One `createLogger('<moduleName>')` per module.

**API design.** Everything under `/api`. Plural nouns for collections, nested child resources, `{ plural: [...] }` / `{ singular: {...} }` / `{ message }` response shapes, `201` on create, `204` on delete, partial `PUT`.

**Error handling.** Handlers throw; Express 5 forwards to `errorHandler`, which turns client mistakes (bad id, validation, duplicate key, bad JSON) into 4xx and everything else into a generic 500 that is logged with method, path and message.

**Validation.** Required fields checked at the route boundary; enums validated with `validateEnum` against model constants; Mongoose validators as the last line of defence (`runValidators: true` on updates).

**Security.** bcrypt (cost 10) password hashes, `select: false` on `passwordHash`, identical 401 for unknown email and wrong password, ownership enforced in queries (404 for other users' data), no fallback JWT secret and a startup check, generic 500 messages, email errors logged by message only.

**Frontend data fetching.** Plain `fetch`, base URL from `VITE_API_BASE`, token from `localStorage.tf_token`, optimistic local state updates after a successful response, notifications re-fetched after each change.

**Config & env.** `.env` (gitignored) from `.env.example`. Required: `JWT_SECRET`, `JWT_EXPIRES_IN`. Optional: `MONGO_URI`, `PORT`, Gmail or SMTP settings. Tests: `MONGO_URI_TEST`.
